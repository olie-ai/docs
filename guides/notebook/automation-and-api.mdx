Uma dúvida recorrente: *dá para enviar o conteúdo do Caderno por uma automação?* A resposta curta é **não**: a automação não alcança o Caderno. A **API** e o **MCP**, sim: os dois leem e escrevem as páginas. Esta página mostra o que cada recurso alcança e qual caminho usar em cada caso.

## O que cada recurso alcança

A tabela compara o Caderno com os dois recursos que costumam ocupar o lugar dele nas integrações:

| Recurso | Caderno | Conteúdo do projeto | Respostas de formulário |
| --- | --- | --- | --- |
| Ler em uma automação | Não | Sim, pela consulta `project_medias` | Sim, direto no contexto |
| Escrever por automação | Não | Sim, pela ação **Envia conteúdo do projeto** | Sim, pela ação [**Preencher formulário dinâmico**](/guides/automation/actions-forms-dates#preencher-formulário-dinâmico). **Atualizar contador** e **Alterar campo de data** também gravam nesses campos, e um agente de IA acionado por **Executar assistente de etapa** pode preencher formulários |
| Ler e escrever pela API | Sim, com a sessão de uma pessoa ou com token de aplicação | Sim | Sim |
| Ler e escrever pelo MCP | Sim | Sim | Sim |
| Copiar ao clonar um projeto | Sim | Sim | Sim |

O conteúdo das páginas do Caderno **não está disponível** para automações. Para integrar, use a [API](#o-caderno-na-api) ou o [MCP](#o-caderno-no-mcp).

## Por que a automação não alcança o Caderno

Alguns campos de uma automação aceitam variáveis: a mensagem, o assunto e o corpo de e-mail e o corpo customizado de webhook. Esses campos leem o que está no **contexto de execução** e completam o que falta com a função `query`.

Nenhuma das consultas disponíveis devolve páginas do Caderno. A que mais se aproxima pelo nome é `project_medias`, e ela traz o **conteúdo publicado no projeto** — a aba **Conteúdo**, não o Caderno. A lista completa está em [Variáveis nas automações](/guides/automation/variables#buscando-dados-adicionais).

## O que fazer no lugar

Na maioria dos casos, o que precisa sair da plataforma é uma informação estruturada — e essa informação costuma já estar em um formulário ou no conteúdo do projeto.

<Tabs>
<Tab title="Enviar respostas de formulário">
  As respostas de formulário já vêm carregadas no contexto, em `project.form_answers`. Não é preciso consulta.

  Uma montagem comum: gatilho **Formulário editado** + ação **Disparar webhook**, com o corpo customizado assim:

  ```twig
  {{ project.form_answers|json(true) }}
  ```

  O filtro `json` com `true` devolve o JSON indentado, o que ajuda a enxergar a estrutura na primeira execução. Depois, recorte só o que interessa.

  Para as respostas de um formulário específico, use a consulta `get_form_answers`. Ela precisa do `pivot`, o endereço que diz onde o formulário está anexado, e esse `pivot` vem pronto da consulta `project_dynamic_forms`:

  ```twig
  Projeto {{ project.code }} — {{ project.name }}
  {% set formularios = query('project_dynamic_forms', { 'project_code': project.code }) %}
  {% for f in formularios %}
    {% set respostas = query('get_form_answers', { 'pivot': f.pivot }) %}
    {{ respostas.response|json(true) }}
  {% endfor %}
  ```

  Veja mais exemplos de consulta em [Sintaxe avançada](/guides/advanced/advanced-syntax).
</Tab>

<Tab title="Enviar o conteúdo do projeto">
  O conteúdo publicado no projeto sai pela consulta `project_medias`:

  ```twig
  {% set conteudos = query('project_medias', { 'project_code': project.code }) %}
  {{ conteudos.medias|json(true) }}
  ```

  Serve quando a informação relevante foi registrada na aba **Conteúdo** — mensagens, arquivos e áudios lançados no projeto.
</Tab>

<Tab title="Escrever de volta na plataforma">
  Para registrar algo automaticamente, o destino é o **Conteúdo do projeto**, com a ação **Envia conteúdo do projeto**. Ela aceita variáveis, pode enviar arquivos anexados de etapa, funil ou formulário, e publica no canal principal, em um canal interno nomeado ou por integração.

  O Caderno não recebe escrita por automação.
</Tab>
</Tabs>

## O Caderno na API

As rotas do Caderno seguem o padrão REST e aceitam tanto a sessão de uma pessoa quanto um token de [aplicação](/api-reference/introduction/authentication). Na API, o Caderno se chama **forum** e cada página se chama **thread**.

| Rota | O que faz |
| --- | --- |
| `GET /api/management/forums?model_class=&model_id=` | Devolve o Caderno de um registro com a lista de páginas. Cria o Caderno, com uma página principal, se o registro ainda não tiver um. `model_class` é, por exemplo, `App\Models\Project` |
| `PATCH /api/management/forums/{forum_id}` | Define a página principal (`default_thread_id`) |
| `POST /api/management/forums/{forum_id}/threads` | Cria uma página vazia (`name`, `order`, `parent_id`) |
| `GET /api/management/forums/{forum_id}/threads/{thread_id}` | Devolve os dados de uma página |
| `PATCH /api/management/forums/{forum_id}/threads/{thread_id}` | Renomeia ou move uma página |
| `DELETE /api/management/forums/{forum_id}/threads/{thread_id}` | Apaga uma página |
| `POST /api/management/forums/{forum_id}/threads/{thread_id}/clone` | Duplica uma página |
| `GET /api/management/forums/{forum_id}/threads/{thread_id}/content` | Devolve o conteúdo da página e a `revision` atual |
| `PUT /api/management/forums/{forum_id}/threads/{thread_id}/content` | Grava o conteúdo inteiro da página. Exige `base_revision` |
| `PATCH /api/management/forums/{forum_id}/threads/{thread_id}/content` | Edita blocos da página com operações em Markdown. Exige `base_revision` |
| `GET /api/management/forums/{forum_id}/threads/{thread_id}/revisions` | Lista as versões da página |
| `POST /api/management/forums/{forum_id}/threads/{thread_id}/revisions/{revision}/restore` | Restaura uma versão antiga como versão nova |

A criação da página não recebe conteúdo: crie a página e depois grave o conteúdo pela rota `content`.

Toda gravação leva a `base_revision`, a versão que você leu. Se outra pessoa salvou depois disso, a resposta é HTTP 409 com `message: "thread_revision_conflict"` e a `current_revision`. Leia de novo e reaplique a sua mudança.

Com a sessão de uma pessoa, ela precisa ter permissão de edição no registro dono do Caderno: `projects.edit.{id}` para projeto, por exemplo. Com token de aplicação, o acesso vale para os registros do workspace do token. Registro de outro workspace responde HTTP 404.

<Note>
As rotas antigas do Caderno (`get-forum`, `create-thread`, `get-thread-data`, `save-thread-data` e outras) continuam funcionando para pessoas, mas estão obsoletas e não aceitam token de aplicação. Use as rotas acima.
</Note>

Ao **clonar um projeto**, o corpo da requisição aceita `forum`, que copia o Caderno do projeto de origem para o clone.

```json Trecho do corpo de POST /api/management/projects/{project}/clone
{
  "name": "Implantação — Cliente novo",
  "forum": true,
  "medias": false
}
```

## O Caderno no MCP

O [MCP da Olie](/guides/mcp/overview) tem quatro ferramentas de Caderno, para projetos, clientes, contatos e usuários:

| Ferramenta | O que faz |
| --- | --- |
| `get-notebook-tool` | Devolve a árvore de páginas do Caderno |
| `read-notebook-page-tool` | Lê uma página em blocos de Markdown |
| `edit-notebook-page-tool` | Edita blocos da página: troca um trecho de texto, substitui, insere ou apaga blocos |
| `create-notebook-page-tool` | Cria uma página. Cria também o Caderno, se o registro ainda não tiver um |

O assistente precisa da mesma permissão de edição que a tela do Caderno exige.

## Se o Caderno é mesmo o alvo

Quando a informação que precisa sair por uma **automação** está no Caderno e não em outro lugar, as saídas são estas:

<CardGroup cols={2}>
<Card title="Copiar da página" icon="copy">
  O conteúdo da página é texto rico comum — selecionar e copiar funciona para levar para outro documento.
</Card>

<Card title="Repetir a informação no lugar certo" icon="arrow-right-arrow-left">
  Se um dado do Caderno precisa circular por integração toda vez, o caminho sustentável é registrá-lo também em um campo de formulário, que a automação alcança.
</Card>
</CardGroup>

<Tip>
Vale medir a necessidade antes: em boa parte dos casos o que a integração precisa não é a página inteira, e sim dois ou três campos. Esses campos rendem mais como formulário dinâmico — ficam consultáveis, filtráveis e disponíveis para automação.
</Tip>
