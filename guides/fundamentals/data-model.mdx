Boa parte dos erros de configuração é um erro de cardinalidade: alguém supôs que cabiam vários onde cabe um só. Esta página é o mapa.

## O desenho geral

```text
Empresa
 └── Área de negócio ......... 0..N   (agrupa funis; opcional)
      └── Funil .............. 0..N
           └── Etapa ......... 1..N   (um funil sem etapas não funciona)

Projeto  ──vincula-se a──►  N funis, ocupando 1 ou mais etapas em cada um
   │
   ├── pai / filho / neto / bisneto ..... 4 níveis (0 a 3)
   ├── Cliente .......................... 1
   ├── Contatos ......................... N
   ├── Usuários atribuídos .............. N
   ├── Grupos de projeto ................ N
   ├── Conteúdo ......................... 1 linha do tempo, com N canais
   ├── Caderno .......................... 0 ou 1 (criado sob demanda)
   └── Formulários ...................... vários, em endereços diferentes
```

## Empresa e usuário

| Relação | Quantos |
| --- | --- |
| Usuário → empresas | **N**, sempre por convite |
| Empresa → usuários | **N** |
| Usuário → empresa Personal | **1**, criada automaticamente no cadastro |
| Usuário → e-mails alternativos (alias) | **N**, com um marcado como principal |

<Note>
A conta **Personal** tem as mesmas funcionalidades de uma conta empresa. A diferença é que ela não permite adicionar outros usuários.
</Note>

### O que existe uma vez por vínculo com funil

Isto é o que mais confunde. Estes itens **não** pertencem ao projeto — pertencem ao par projeto + funil, e por isso existem uma vez para cada funil em que ele está:

- A **etapa** que ele ocupa naquele funil
- O **status do funil**
- A **data de previsão** e o contador de alterações dela
- As respostas do **formulário do funil** e dos formulários das etapas daquele funil

Ver [o modelo mental](/guides/fundamentals/mental-model).

## Formulários

O ponto que mais gera erro. Um formulário **não pertence a nada** — ele é anexado a lugares, e acumula um conjunto de respostas em cada um.

| Onde | Quantos por registro |
| --- | --- |
| Objeto **Projeto** | 1 por conta, valendo para todos os projetos |
| Objeto **Cliente** | 1 por conta |
| Objeto **Contato** | 1 por conta |
| Objeto **Usuário** | 1 por conta |
| **Funil** | 1 por funil |
| **Etapa** | 1 por etapa |
| **Avulso** no projeto | **N**, e o mesmo formulário pode repetir |

Ver [Formulários dinâmicos](/guides/forms/overview) e, para o endereçamento na API, [o pivot](/api-reference/general/form-answer-pivot).

## Etiqueta e status

| | Etiqueta | Status do funil |
| --- | --- | --- |
| Quantos por projeto | **N** | **1 por funil** |
| Onde é criada | No funil | No funil |
| Onde aparece depois de aplicada | **Em todos os funis** onde o projeto está | **Só naquele funil** |
| Pode ser conclusivo | Não | Sim |

<Note>
É por isso que o mesmo item pode estar verde em um funil e vermelho em outro — isso é status — e ao mesmo tempo aparecer como "Urgente" nos dois — isso é etiqueta.
</Note>
