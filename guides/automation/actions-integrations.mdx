## Envia conteúdo do projeto

Publica uma mensagem no conteúdo do projeto. É a ação mais usada para comunicar o que a automação fez.

<Note>
O destino é a aba **Conteúdo** do projeto, não o [Caderno](/guides/notebook/overview) — são recursos diferentes, e o Caderno não recebe escrita por automação.
</Note>

| Opção | Obrigatória | O que faz |
| --- | --- | --- |
| Mensagem | Sim | O texto publicado; aceita variáveis |
| Destino | Não | Onde a mensagem é publicada |

### Os três destinos

<Tabs>
<Tab title="Canal principal">
  A mensagem é publicada solta no conteúdo do projeto, como qualquer registro que uma pessoa escreveria. É o padrão.
</Tab>

<Tab title="Canal interno nomeado">
  A mensagem vai para um canal interno com nome, separando esse tipo de registro do restante do conteúdo. **Se o canal não existir no projeto, ele é criado.**

  Útil para separar avisos automáticos ("Log de automações") do que a equipe conversa.
</Tab>

<Tab title="Linha externa (via integração)">
  A mensagem é enviada para fora, por uma integração de comunicação, abrindo ou reaproveitando uma conversa com o destinatário.

  | Opção | Obrigatória | O que faz |
  | --- | --- | --- |
  | Integração | Sim | Qual integração de comunicação será usada |
  | Destinatário | Não | O endereço de destino; aceita variáveis. Em branco, usa a conversa que o projeto já tem nessa integração |
  | Reabrir conversa ativa | Não | Encerra uma conversa ativa em outro projeto e abre uma nova aqui |
  | Motivo do encerramento | Não | Nota registrada na conversa encerrada |

  **Destinatário em branco:** a mensagem vai para a conversa que o projeto já tem nessa integração, inclusive retomando um atendimento encerrado com o mesmo contato. Isso só funciona quando o projeto conversa com **um único contato** naquela integração — várias conversas com a mesma pessoa, encerradas e reabertas, contam como uma. Se o projeto não tiver conversa nessa integração, ou tiver com mais de um contato, a mensagem não sai e a ação registra erro pedindo um destinatário.

  **Destinatário preenchido:** o endereço é mantido **exatamente como a expressão devolver** — a plataforma não normaliza o formato. Se a expressão não devolver nada, a ação registra erro e a mensagem não sai; ela não recorre à conversa que o projeto já tem.

  <Note>
  Este destino só aparece quando existe alguma integração de comunicação ativa na conta.
  </Note>
</Tab>
</Tabs>

### Mencionar pessoas

Menções dentro de uma automação precisam do formato de menção, que você pode montar com variáveis. Veja [Mencionar usuários com automação](/guides/automation/mention-users).

## Enviar um e-mail

Envia um e-mail. Assunto e mensagem aceitam variáveis.

| Opção | Obrigatória | O que faz |
| --- | --- | --- |
| Emails | Sim | Destinatários, separados por vírgula |
| Assunto | Sim | Assunto do e-mail; aceita variáveis |
| Mensagem | Sim | Corpo do e-mail; aceita variáveis |

O campo de destinatários também aceita uma expressão que devolve os endereços. Nesse caso, o resultado é separado por vírgula e cada endereço é validado — os inválidos são descartados e os repetidos, unificados.

<Warning>
Se, depois de calcular a expressão, nenhum endereço válido sobrar, a ação registra `invalid_emails` e nenhum e-mail é enviado.
</Warning>

<Note>
O envio é enfileirado, não instantâneo. O registro de execução marca a ação como bem-sucedida quando o e-mail entra na fila, não quando chega na caixa de entrada.
</Note>

<Tip>
Envio de e-mail é irreversível. Ao montar automações com gatilhos de alto volume — formulário editado ou projeto ocioso com repetição — pense no número de mensagens antes de ativar.
</Tip>

## Disparar webhook

Notifica um sistema externo sobre o que aconteceu.

| Opção | Obrigatória | O que faz |
| --- | --- | --- |
| Endpoint | Sim | A URL que vai receber a requisição |
| Corpo customizado | Não | Conteúdo extra enviado junto; aceita variáveis |

### O que é enviado

A requisição é sempre **`POST`**, com o corpo em JSON:

| Campo | O que traz |
| --- | --- |
| `event` | O tipo do gatilho que acionou a automação |
| `created_at` | O momento do disparo |
| `data` | Os dados do gatilho |
| `custom_body` | O corpo customizado já calculado — como objeto, se o texto resultante for um JSON válido; como texto, caso contrário |

<Warning>
**Não é possível escolher o método nem enviar cabeçalhos.** A chamada sai sempre como `POST`, sem cabeçalhos customizados — não há campo de `Authorization`, de chave de API ou de assinatura.

Na prática, isso significa que a ação **não serve para chamar uma API que exija autenticação por cabeçalho** — inclusive a [API da própria Olie](/api-reference/introduction/authentication). O destino precisa aceitar uma chamada sem credencial no cabeçalho.
</Warning>

<Tip>
Quando o destino exige credencial, aponte o webhook para um endereço intermediário seu — uma função, um endpoint próprio ou uma ferramenta de automação externa. Ele recebe a chamada aberta, confere o que precisar pelo corpo e só então chama a API autenticada.
</Tip>

### Como a chamada é feita

A chamada é **síncrona**: a automação espera a resposta antes de seguir para a próxima ação. O tempo máximo de espera é de **10 segundos**.

| Resposta do endpoint | O que acontece |
| --- | --- |
| **200** | O componente é marcado como sucesso |
| Qualquer outro código | O componente é marcado como erro |
| Nenhuma resposta em 10 segundos | O componente é marcado como erro |

Redirecionamentos não são seguidos — um `301` ou `302` conta como erro, e não como a resposta do endereço de destino.

O erro fica registrado naquele componente e **o fluxo continua** nas ações seguintes.

<Note>
O endpoint precisa ser **público**. Endereços que apontam para a rede interna — `localhost`, faixas privadas, endereços reservados — são recusados antes do envio. Um webhook para um sistema que roda dentro da sua rede não funciona sem um endereço acessível pela internet.
</Note>

<Tip>
O editor tem um botão **Testar webhook**. Use antes de salvar para confirmar que o endpoint responde. O teste envia um corpo com `event` igual a `test` e dados de exemplo — não os dados de um projeto real.
</Tip>

### A resposta não volta para o fluxo

<Warning>
**O corpo da resposta não volta para a automação.** O que o endpoint devolve não vira variável e não pode ser usado em uma condição nos passos seguintes. Do retorno, o fluxo aproveita uma única informação: se a chamada respondeu 200 ou não.
</Warning>

Ou seja: não dá para consultar um sistema externo no meio da automação e continuar com o dado consultado. Para reagir a uma informação de fora, inverta a direção — quem escreve na Olie é o serviço externo:

<Steps>
<Step title="A automação dispara o webhook" icon="paper-plane">
  Com o corpo customizado levando o que o serviço externo precisa saber — o identificador do projeto, por exemplo.
</Step>

<Step title="O serviço externo processa" icon="gears">
  No tempo dele, sem prender a automação.
</Step>

<Step title="O serviço escreve de volta na Olie" icon="arrow-rotate-left">
  Pela [API](/api-reference/introduction): preencher um campo de formulário, aplicar uma etiqueta, mover o projeto de etapa.
</Step>

<Step title="Essa escrita dispara outra automação" icon="bolt">
  O gatilho correspondente — formulário editado, etiqueta vinculada, projeto movido — retoma o processo já com o dado em mãos.
</Step>
</Steps>

<Note>
Uma automação acionada por outra conta no [limite de encadeamento](/guides/automation/anatomy#automações-que-acionam-automações). A escrita feita por um serviço externo, não: para a plataforma, é uma escrita como qualquer outra.
</Note>

## Executar assistente de etapa

Aciona um assistente de etapa, a peça de IA que analisa o projeto e produz um resultado dentro dele.

| Opção | Obrigatória | O que faz |
| --- | --- | --- |
| Assistente de etapa | Sim | Qual assistente será executado |

<Note>
A lista mostra apenas assistentes configurados como **execução manual** ou com a execução manual habilitada. Assistentes que rodam automaticamente na etapa não aparecem aqui — eles já têm gatilho próprio.
</Note>

<Warning>
Assistentes consomem créditos de IA da conta. Combinar esta ação com um gatilho de alto volume consome créditos na mesma proporção. Veja [Créditos de IA](/guides/billing/ai-credits).
</Warning>

## Atualizar progresso de meta manual

Soma, subtrai ou define o progresso de uma meta do tipo manual.

| Opção | Obrigatória | O que faz |
| --- | --- | --- |
| Meta | Sim | A meta manual afetada |
| Ação | Sim | Incrementar, decrementar ou definir |
| Valor | Sim | Um número ou uma expressão que devolva um número |

<Warning>
A meta precisa ser do tipo **manual** e estar **ativa**. Metas de outros tipos calculam o próprio progresso e não aceitam esta ação — nesse caso o componente registra erro sem alterar nada.
</Warning>

O progresso nunca fica abaixo de zero: uma subtração maior que o valor atual resulta em zero.

## Controlar execução de projeto

Inicia ou pausa a contagem de tempo de um projeto para usuários específicos.

| Opção | Obrigatória | O que faz |
| --- | --- | --- |
| Tipo de ação | Sim | Iniciar execução ou pausar execução |
| Usuários alvo | Sim | De onde vem a lista de usuários afetados |
| Etapa | Não | Ao iniciar, a etapa vinculada à execução |

### De onde vêm os usuários

| Origem | Comportamento |
| --- | --- |
| Usuário que disparou o gatilho | Usa quem causou o evento |
| Usuários selecionados | Usa a lista que você escolher |
| Sintaxe avançada | Usa a lista devolvida por uma expressão |

<Warning>
A origem **Usuário que disparou o gatilho** exige que o disparo tenha vindo de uma pessoa. Em automações acionadas por agendamento — projeto ocioso ou data atingida — não existe usuário causador e a ação registra `invalid_causer_type`.
</Warning>

### Iniciar

Ao iniciar, a execução é vinculada à etapa escolhida. Sem etapa selecionada, a ação usa a etapa que acionou a automação — o que exige um gatilho ligado a uma etapa. Com um gatilho que não é de etapa e sem etapa escolhida, a ação registra `trigger_not_step_scoped`.

### Pausar

Ao pausar, todas as execuções em andamento daqueles usuários **naquele projeto** são encerradas, registradas como parada programada.

<Tip>
O par mais útil: gatilho [Execução de projeto](/guides/automation/triggers#execução-de-projeto) no evento **Iniciar**, com esta ação em **Pausar** — garantindo que ninguém fique com duas execuções abertas ao mesmo tempo.
</Tip>
