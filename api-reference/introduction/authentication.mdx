Toda requisição à API precisa de um token de acesso. Esta página mostra como enviar o token, como obtê-lo criando uma aplicação na Olie e o que saber sobre validade, troca e permissões do token.

## Enviar o token na requisição

A API identifica quem faz a chamada pelo token de acesso de uma **aplicação**, a credencial de integração da Olie. Envie o token no cabeçalho `Authorization`, com o prefixo `Bearer ` antes dele:

```bash cURL
curl -H "Authorization: Bearer {{token_de_acesso}}" https://api.olie.ai/api/management/projects
```

O prefixo `Bearer ` é obrigatório. Sem ele, a API trata a requisição como não autenticada e responde com HTTP 401.

<Warning>
  Mantenha o token em segurança. Nunca compartilhe o token nem o coloque em repositórios públicos.
</Warning>

## Obter o token de acesso

O token é gerado quando você cria uma aplicação nos ajustes da empresa.

<Steps>
  <Step title="Abra Aplicações">
    Entre na sua empresa em https://olie.ai/frames e vá em **Ajustes** > **Integrações** > **Aplicações**.

    <Frame caption="Aplicações fica no grupo Integrações do menu de Ajustes">
      <img src="/images/api-reference/ajustes-integracoes-aplicacoes.png" alt="Menu lateral de Ajustes com os itens Papéis e Ajustes da empresa e, abaixo, o grupo Integrações com Aplicações contornado, seguido de Webhooks, MCP e Integrações" />
    </Frame>
  </Step>
  <Step title="Crie uma aplicação">
    Clique em **Criar aplicação** e preencha os campos obrigatórios. A plataforma mostra o token de acesso gerado.

    <Warning>
      Guarde o token em um local seguro. A plataforma não mostra o token de novo.
    </Warning>
  </Step>
  <Step title="Use o token">
    Envie o token no cabeçalho `Authorization` das requisições, como em [Enviar o token na requisição](#enviar-o-token-na-requisição).

    <Check>
      Se a requisição responder com HTTP 200 e `"response": true`, o token está funcionando.
    </Check>
  </Step>
</Steps>

## Ciclo de vida do token

O token nasce junto com a aplicação e não muda mais. Planeje a integração considerando as características abaixo.

| Característica | Comportamento |
| --- | --- |
| Tokens por aplicação | Um. O token é gerado quando a aplicação é criada. |
| Exibição | Uma única vez, na resposta da criação. Depois disso a plataforma não mostra mais o valor. |
| Validade | 1 ano a partir da criação. |
| Renovação | Não existe. Não há endpoint para renovar, rotacionar ou gerar um segundo token. |
| Revogação | Excluir a aplicação revoga o token dela — e só o dela. |
| Quantidade de aplicações | Sem limite. |
| Empresa | O token é fixo na empresa em que a aplicação foi criada. |

Se você perder o token, não há como recuperá-lo. Crie outra aplicação e use o token novo.

### Trocar um token

Como não há rotação, você troca o token substituindo a aplicação:

<Steps>
  <Step title="Crie uma nova aplicação">
    Guarde o novo token com segurança.
  </Step>
  <Step title="Aponte a integração para o novo token">
    Faça a virada no seu lado e confirme que as chamadas continuam funcionando.
  </Step>
  <Step title="Exclua a aplicação antiga">
    Exclua a aplicação em **Ajustes** > **Integrações** > **Aplicações**, com um usuário que tenha a permissão `applications.create`. A exclusão revoga apenas o token daquela aplicação. As demais aplicações da empresa seguem funcionando normalmente.

    O endpoint `DELETE /api/management/applications/{id}` é reservado a pessoas. Uma chamada feita com token de aplicação recebe HTTP 403 com `message: "access_denied_for_applications"`.
  </Step>
</Steps>

<Tip>
  Como não há limite de aplicações, você pode manter a antiga e a nova ativas durante a virada. Exclua a antiga só depois de confirmar que ninguém mais a usa.
</Tip>

### Expiração

O token expira 1 ano depois de criado, sem aviso prévio. A partir daí, as requisições com esse token respondem com HTTP 401. Registre a data de criação do lado da integração e troque o token antes do vencimento.

## Segurança e permissões

Uma aplicação tem **acesso total** dentro da empresa a que pertence. Não existe escopo por permissão: não é possível criar uma aplicação que só leia projetos, ou que não enxergue clientes.

<Warning>
  O token de uma aplicação equivale a um acesso privilegiado à empresa inteira. Trate-o como uma credencial de administrador: nunca o exponha em repositórios, front-ends ou logs.
</Warning>

O token tem dois limites:

- **Uma empresa só.** O token enxerga apenas os dados da empresa em que a aplicação foi criada.
- **Nem todos os endpoints.** Alguns endpoints são reservados a pessoas e recusam aplicações com HTTP 403 e `message: "access_denied_for_applications"`.

### Autoria no histórico

Tudo que a aplicação altera fica no [registro de alterações](/api-reference/general/audit-log) com a **própria aplicação** como autora, e não com o usuário que criou a aplicação. Se você precisa distinguir o que cada integração fez, crie uma aplicação por integração.

### Quando usar o MCP

O servidor MCP é outro caminho de acesso à Olie. Nele, a autenticação é feita por **OAuth** e **como usuário**, não como aplicação. As chamadas passam pelas permissões desse usuário, e o histórico registra o nome dele. O MCP também tem um limite de requisições próprio, separado do limite da API.

Use o MCP quando o acesso deve refletir o que uma pessoa pode fazer, e a API com token de aplicação quando a integração é servidor-a-servidor. Veja [MCP](/guides/mcp/overview).

## Erros de autenticação

Estas respostas indicam problema com o token ou com o acesso da aplicação:

| Resposta | Causa | Como resolver |
| --- | --- | --- |
| HTTP 401, `message: "unauthorized"` | O cabeçalho `Authorization` está ausente, sem o prefixo `Bearer ` ou com um token inválido, expirado ou de uma aplicação excluída. | Confira o formato `Authorization: Bearer {{token_de_acesso}}`. Se o token expirou ou a aplicação foi excluída, crie outra aplicação e use o token novo. |
| HTTP 403, `message: "access_denied_for_applications"` | O endpoint é reservado a pessoas e não aceita token de aplicação. | Faça essa operação pela interface da Olie, com um usuário que tenha permissão para ela. |

Exemplo de resposta 401:

```json
{
  "response": false,
  "message": "unauthorized",
  "error": "Unauthenticated."
}
```
